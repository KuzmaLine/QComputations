# QComputations — авто-документация через Doxygen

Готовая заготовка авто-документации для ядра `src/QComputations`
(C++/CUDA). Собирает HTML-референс API + класс-/call-диаграммы.

## Состав

| Файл               | Назначение                                   |
|--------------------|----------------------------------------------|
| `Doxyfile`         | Конфигурация Doxygen (шаблон с плейсхолдерами)|
| `generate.sh`      | Обёртка: подставляет плейсхолдеры и запускает |
| `mainpage.md`      | Титульная страница (главная страница доков)   |
| `Doxyfile.generated` | Временный результат подстановок (создаётся при запуске) |
| `../doxygen_html/` | Итоговые HTML-доки (создаются при запуске)    |

## 1. Установка зависимостей

Нужны только два пакета (в WSL / Ubuntu):

    sudo apt-get install -y doxygen graphviz

* `doxygen` — обязательный (собирает доки).
* `graphviz` — опциональный, нужен для `dot`-диаграмм (классы, вызовы).
  Без него скрипт отключит диаграммы, но сам HTML соберётся.

Проверка: `doxygen --version` и `dot -V`.

## 2. Генерация

    cd doxygen
    ./generate.sh            # базовый вариант single (CPU / oneAPI)

Результат откроется в браузере (или `xdg-open ../doxygen_html/index.html`).
Если не хочешь авто-открывания: `./generate.sh single --no-open`.

### Варианты сборки

    ./generate.sh single          # базовый: CPU, Intel oneAPI (ENABLE_ONEAPI)
    ./generate.sh cluster         # + кластер: ENABLE_CLUSTER ENABLE_MPI
    ./generate.sh cuda            # CUDA-ядро (__CUDACC__ + файлы .cu)
    ./generate.sh blocked_cuda    # blocked CUDA

Каждый вариант задаёт свой набор `PREDEFINED` (feature-макросы) и список
расширений исходников (`FILE_PATTERNS`), поэтому доки соответствуют реальному
API выбранного бэкенда.

## 3. Что собирается

* `doxygen_html/index.html` — корневая страница.
* Дерево: классы / пространства имён / файлы / группы.
* Поиск по API.
* Call-/callee- и класс-диаграммы (если установлен `graphviz`).
* Титульная страница из `mainpage.md`.

## 4. Как описывать код (важно!)

Сейчас в исходниках почти нет док-аннотаций (`@brief` = 0), поэтому
включено `EXTRACT_ALL` — доки строятся для всех символов, но без текста.
Чтобы референс был полезным, добавляй краткие описания перед объявлением:

    /// Диагонализация временно-зависимого гамильтониана.
    /// @brief Считает собственные значения методом Lanczos.
    /// @param H   матрица гамильтониана
    /// @return   отсортированные собственные значения
    void eigen();

Правила:
* `///` — однострочный brief; `/** ... */` — блок с деталями.
* `@brief` — краткое; `@param [in] x` — аргумент; `@return` — результат.
* `@tparam T` — параметр шаблона; `@note`, `@see`, `@sa` — примечания/ссылки.
* Блок ставится СРАЗУ перед функцией/классом/переменной, без пустой строки.

Когда начнёшь добавлять `@brief`, включи контроль: в `Doxyfile` поставь
`WARN_IF_UNDOCUMENTED = YES`, чтобы виднелись недок-символы.

## 5. Настройка / тюнинг

В `Doxyfile`:
* `OUTPUT_LANGUAGE = Russian` — язык подписей UI. Для англ. доков поменяй
  на `English` (идентификаторы не меняются, меняется только навигация).
* `SKIP_FUNCTION_BODIES = YES` — доки по сигнатурам. Поставь `NO`, чтобы
  вставлять тела функций.
* `EXCLUDE_PATTERNS` — сейчас вырезает сторонние `exprtk.hpp`,
  `matplotlibcpp.hpp`. Добавляй сюда другие вендор-файлы.
* `HAVE_DOT` / `MAX_DOT_GRAPH_NODES` — диаграммы и их размер.
* `PREDEFINED` — если в новом варианте появляются новые `#ifdef`-макросы,
  допиши их сюда (для своего варианта — в `generate.sh`, в ветку `case`).

## 6. Типовые проблемы

* **CUDA-парсинг.** `.cu`-файлы парсятся как C++; `<<< >>>` (запуск
  ядер) и `__global__/__device__` иногда дают warnings. Это не ломает
  сборку. Если шума слишком много — убери `*.cu` из `FILE_PATTERNS`
  для CPU-вариантов (в скрипте и в `Doxyfile`).
* **Неизвестные `#ifdef`.** Если доки «теряют» куски кода — значит,
  нужный макрос не задан в `PREDEFINED`. Добавь его (в скрипте под вариант).
* **Диаграммы не рисуются.** Не установлен `graphviz` — см. п.1.
* **`doxygen` не найден.** Не установлена — см. п.1.

размещать каталог `../doxygen_html/` как артефакт (например, в Pages/Artifacts).
